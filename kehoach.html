IDE chạy test Playwright trên trình duyệt

Đánh giá source playwright-cheatsheet hiện tại và checklist thực thi. Bản song song của kehoach.md — tick được, tự lưu vào trình duyệt.

0. Kết luận trước, giải thích sau

1
Playwright không chạy được trong trình duyệt.

Nó cần spawn process, ghi file và điều khiển một binary Chromium thật. "IDE chạy Playwright trên trình duyệt" thực chất là: soạn thảo trên trình duyệt, thực thi trên server. WebContainer/WASM không cứu được — chúng chạy Node được, chạy Chromium thì không.

2
Repo hiện tại là site tĩnh 100%.

output: "export" trong next.config.ts. Ở chế độ này Next.js liệt kê rõ trong mục Unsupported Features: "Route Handlers that rely on Request". Không có POST thì không có nút RUN. Phải chọn: bỏ static export, hoặc tách IDE ra origin riêng.

3
Vercel serverless không phải chỗ chạy npx playwright test.

Filesystem chỉ ghi được /tmp và bay sau mỗi lần chạy; bundle có trần dung lượng trong khi browser của Playwright nặng hàng trăm MB; Firefox/WebKit gần như bất khả thi. Kế hoạch cũ đặt "tách runner ra Docker" ở Phase 9 — nên đảo lại và tách ngay từ đầu, làm hai lần thì phí.

Khuyến nghị. Next.js trên Vercel làm IDE + API mỏng, gọi sang một runner riêng chạy Docker image chính thức của Playwright. Ở MVP: không Redis, không BullMQ, không Kubernetes.

1.3 Năm xung đột kiến trúc phải xử lý

①
output: "export" chặn API.

Cách A (khuyến nghị): bỏ output: "export", deploy Vercel bình thường. 341 trang vẫn được prerender tĩnh vì đã có generateStaticParams() + dynamicParams = false. Mất khả năng "deploy lên CDN bất kỳ", đổi lấy backend — đáng. Cách B: giữ site tĩnh, IDE ở origin khác → CORS, hai lần deploy, không chia sẻ layout.

②
trailingSlash: true là bẫy cho POST.

Next sẽ redirect /api/run → /api/run/, và nhiều client mất body khi bị redirect trên POST. Hoặc luôn gọi URL có dấu / cuối, hoặc đặt skipTrailingSlashRedirect. Loại lỗi mất nửa ngày để tìm.

③
Shiki không được lọt vào bundle client.

lib/highlight.ts đã ghi rõ cảnh báo này. Trang IDE là Client Component; import nhầm CodeBlock vào đó là kéo vài MB grammar xuống trình duyệt. Editor phải dùng bộ tô màu riêng.

④
Monaco nặng gấp nhiều lần toàn bộ site hiện tại.

Site đang tự hào vì trang chi tiết "không cần một byte JS nào"; Monaco ~2–5 MB. Bắt buộc next/dynamic với ssr: false, chỉ ở route /ide, tuyệt đối không đặt trong app/layout.tsx.

⑤
Chạy code người dùng gửi lên = RCE có chủ đích.

npx playwright test trên file do người lạ soạn nghĩa là họ chạy Node tuỳ ý trong hạ tầng của bạn: process.env, đọc file, gọi API nội bộ, đào coin, dùng server của bạn tấn công bên thứ ba. Kế hoạch cũ xếp Security ở Phase 7 — quá muộn. Đây là P0.

5. Định nghĩa "MVP xong"

Đủ cả sáu gạch đầu dòng mới coi là xong:

  1. Người dùng mở /ide, thấy editor có sẵn một test mẫu.
  2. Ctrl+K → tìm getByRole → code mẫu được chèn vào editor.
  3. Bấm RUN → log chạy hiện dần theo thời gian thực.
  4. Test fail → thông điệp lỗi rõ ràng + screenshot + video + link trace.
  5. Reload trang → code vẫn còn (localStorage).
  6. Đã chạy đủ bộ kiểm thử phá hoại ở P1 và tất cả đều bị chặn.

Mọi thứ khác — Firefox/WebKit, database, project, chạy song song, Redis, BullMQ — đều ở sau vạch này.

6. Việc làm ngay

  1. Chốt phương án ở P0 (bỏ static export hay tách origin).
  2. Bỏ output: "export", chạy npm run build, xác nhận vẫn ra 341 trang tĩnh.
  3. Dựng Dockerfile runner + chạy được npx playwright test trên một file cứng.
  4. Chỉ khi bước 3 xong mới bắt đầu đụng vào Monaco.
